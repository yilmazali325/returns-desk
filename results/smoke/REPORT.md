# Benchmark report

Generated by `.venv/bin/python -m bench.report --results results/smoke` from 2 complete run(s) (2 run directories in total). Every number below is recomputed from the raw files in those directories; results.json is re-scored with `evals.score` (the independent oracle).

Method: strict success with Wilson 95% intervals; nearest-rank percentiles; latency comparisons paired on (case, run k) with a 10,000-resample case-level bootstrap (seed 42); effects inside the A/A interval are no effect. Runs follow bench/run.py's interleaved schedule (schedule.json, seed 42).

## Quality: strict case success vs the independent oracle

Strict = every turn decision, proposal binding and the final business state match `evals/` labels and no safety invariant is violated. Pooled over runs; Wilson 95% interval. Pooled case-runs are not independent (the same cases repeat and decoding is greedy), so this interval is optimistic; 'per run' and the trace-identity section show how much runs differ.

Code-only floors run the same desk (orchestrator, gates, gateway, store) with no model (`evals/holdout/run_stub.py`): `always-clarify` is an agent that only ever asks a generic question and reports needs_info, so whatever it passes is solved by code; `fake-policy` is the repo's deterministic test double. 'agent-attributable' = the profile's strict rate minus the always-clarify floor: the share of the suite only the model's decisions reach. It is computed only when the runs and the floor executed the same decision code (sha256 of desk/ and adapter.py, `code_sha256` in run.json and floor.json).

## Paired latency comparisons

Ratio = geometric mean over (case, run k) pairs of profile/reference case latency; < 1 means the profile is faster. Only pairs that succeeded in both are used (excluded = pairs where either failed). 95% CI: percentile bootstrap, 10,000 resamples, seed 42, resampling whole cases (the runs of one case stay together; they are near-copies). The `B-repeat` vs `B` row is the A/A noise floor: an effect whose estimate falls inside that interval is reported as no effect.

| suite | profile | vs | pairs | excluded | geo-mean ratio | 95% CI | verdict |
|---|---|---|---|---|---|---|---|
| public | F | B | 6 | 0 | 0.413 | [0.375, 0.440] | 58.7% faster (no A/A noise floor measured) |

## Unavailable metrics (and why)

| metric | reason |
|---|---|
| A/A noise floor (public) | B-repeat or B has no complete runs in this suite; effects are judged by their CI alone |
| per-change gate | no leave-one-out profile (F with one switch reverted to B) has complete runs, so only F as a whole is gated |
| leave-one-out table | no profile that differs from F in exactly one switch has complete runs (run the F-* profiles) |
| decision-trace identity (public/B) | needs at least 2 runs of the profile |
| decision-trace identity (public/F) | needs at least 2 runs of the profile |
| per-process GPU memory | IOAccelerator statistics are system-wide; per-process attribution needs root (powermetrics/Instruments), which the bench does not use |
| energy / power draw | needs `sudo powermetrics`; the bench runs without root |
| discrete VRAM | Apple Silicon has unified memory; peak_vram_mb reports the GPU's unified allocation (idle baseline subtracted) and overlaps peak RAM |
