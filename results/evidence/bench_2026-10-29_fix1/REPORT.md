# Benchmark report

Generated by `.venv/bin/python -m bench.report --results results` from 33 complete run(s) (33 run directories in total). Every number below is recomputed from the raw files in those directories; results.json is re-scored with `evals.score` (the independent oracle).

Method: strict success with Wilson 95% intervals; nearest-rank percentiles; latency comparisons paired on (case, run k) with a 10,000-resample case-level bootstrap (seed 42); effects inside the A/A interval are no effect. Runs follow bench/run.py's interleaved schedule (schedule.json, seed 42).

## Quality: strict case success vs the independent oracle

Strict = every turn decision, proposal binding and the final business state match `evals/` labels and no safety invariant is violated. Pooled over runs; Wilson 95% interval. Pooled case-runs are not independent (the same cases repeat and decoding is greedy), so this interval is optimistic; 'per run' and the trace-identity section show how much runs differ.

Code-only floors run the same desk (orchestrator, gates, gateway, store) with no model (`evals/holdout/run_stub.py`): `always-clarify` is an agent that only ever asks a generic question and reports needs_info, so whatever it passes is solved by code; `fake-policy` is the repo's deterministic test double. 'agent-attributable' = the profile's strict rate minus the always-clarify floor: the share of the suite only the model's decisions reach. It is computed only when the runs and the floor executed the same decision code (sha256 of desk/ and adapter.py, `code_sha256` in run.json and floor.json).

## Pre-registered acceptance gate

Per change we also require F >= F-without-that-change on the public suite, so a change cannot ride on the others. Otherwise F keeps B's choice.

## Latency
